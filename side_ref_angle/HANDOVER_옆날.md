# 옆날 마모 측정 — 로직 정리 및 인수인계

엔드밀 **옆면(flank) 사진**으로 새 공구 대비 마모 공구의 **절삭날 후퇴량(µm)** 을
자동 측정하는 파이프라인. 이 문서 하나로 이어서 작업할 수 있게 정리했다.

- 저장소: `https://github.com/himinji/MAENG-Tool-Wear`
- 이 문서 기준 커밋: `6adc9b2`
- 관련 코드: `side_ref_angle/` (옆날), `botface_pipeline.py`+`tool_wear_v2/` (아랫날), `monitor_gui_v5.py` (GUI)

---

## 0. 30초 요약

1. 공구를 1회전 촬영한 420장에서 **레퍼런스 각도**(두 날끝이 세로로 가장 벌어진 각)를 찾는다 → 여기서 **µm/px 스케일**이 나온다.
2. 거기서 정해진 만큼 돌린 **판별 프레임**을 새/마모 각 2장씩 고른다 (날이 2개니까).
3. 그 프레임을 **날끝 기준으로 크롭**해 **SAM**으로 날 영역을 잡는다.
4. 마모 후보 ±3장 중 **같은 회전 각도**인 것을 RMSE로 고른다.
5. 새/마모 외곽선을 정렬한 뒤 **위 경계(절삭날)의 차이 = 마모**를 잰다.


- `Toolwear/옆` 이 없으면 `옆` 폴더, 그것도 없으면 지정한 폴더 자체를 쓴다 (GUI `side_folder()`).
- **백라이트 촬영** 필수: 배경 흰색(밝기 255), 공구는 어두운 실루엣. 이진화 임계값 **210** 이 이 전제에 걸려 있다.
- 3088×2076 그레이스케일 PNG, 파일명 `img_####.png`.

- **2날 180° 대칭** 전제. 3날 이상이면 피크/계곡 선정과 날 짝짓기를 일반화해야 한다.

## 2. 파이프라인 상세

### 단계 1 — 레퍼런스 각도 스캔 (`find_ref_angle.py`)

420장 각각에서:

1. **이진화** — 밝기 < 210
2. **공구 분리** — 오른쪽 가장자리 씨앗과 연결된 덩어리만 (조명·치구 배제)
3. **상/하 분할** — 이미지 중심 y 기준
4. **날끝 2점 검출** — 반쪽별 최좌단 x 확정 → **+20px 밴드** 안에서 y 극값
   (밴드를 두는 이유: 둥근 모서리의 꼭대기까지 잡기 위해. `--x-tol`)
5. **y_diff 기록** — 두 점의 세로 거리

420장을 이으면 **|cos|형 쌍봉 곡선**이 나온다.

- **피크** = 두 날끝이 세로로 최대 = 직경 방향 → 여기서 **스케일** 산출
  `µm/px = 직경(8mm) / 새 공구 피크 y_diff`
  (코팅 1660px → 4.819µm/px, ALUCUT 1620px → 4.940µm/px)
- **계곡** = 피크에서 90° 돌아간 각도
- 산출물: `ref_angle_scores.csv` (420행), `ref_angle_plot.png`

> **스케일은 항상 새 공구 기준**이다. 마모 공구의 피크는 쓰지 않는다.

### 단계 2 — 판별 프레임 선정

**판별 프레임 = 계곡 + 고정 오프셋 20장** (`--offset`, 기본 20)

계곡 정각을 쓰지 않는 이유: 그 각도에서는 **반대날 끝면 덩어리가 날끝과 투영으로 겹쳐**
SAM 마스크가 오염된다. 겹침이 풀릴 때까지 돌려야 하고, 그 필요 장수를 **고립 경계**라 부른다
(날끝 위로 뻗은 실루엣 높이 M=0 이 2연속 되는 첫 지점). 실측: 새 공구 +8~9, Test44 +12~15, Test43 +13~18.

오프셋을 **상수로 고정**한 이유: 예전에는 새/마모의 고립 경계 최댓값을 썼는데, 그러면
**마모 세트가 바뀔 때마다 새 공구 판별 프레임까지 달라져** 테스트 간 비교가 불가능했다.
고정하면 새 공구 프레임이 항상 같다. 고립 경계+2 가 오프셋을 넘으면 경고를 찍는다
(`--offset auto` 로 옛 방식 복귀 가능).

### 단계 3 — 고정 좌표 크롭 (`--sam-crop on`)

- **R = 새 공구 피크 y_diff / 2** (= 반경, 코팅 830px)
- 창 = `x ∈ [ref_x − R/2, ref_x + R]`, **세로는 자르지 않음**
- `ref_x` = 새 공구 레퍼런스 피크 2장의 날끝 x 평균
- **모든 사진(새·마모)에 같은 좌표를 적용** — 사진마다 자기 날끝으로 자르면 절단 위치가 달라져
  RMSE 비교가 오염된다. 고정 창으로 바꾼 뒤 위상 선택 여유가 0.8 → 18.8µm 로 회복됐다.

크롭 효과: SAM 내부 축소율 3.0배 → 2.0배로 완화.

### 단계 4 — SAM 날 영역 검출 (`sam_blade_detect.py`)

크롭 이미지에 점 4개를 준다:

| 역할 | 위치 |
|---|---|
| 양성 ① 클릭 | 날끝 오른쪽 150~450px 띠, 축 아래 실루엣의 무게중심 |
| 양성 ② tip_in | 날끝에서 클릭 방향 60px 안쪽 |
| 음성 ① | **반대쪽(위) 웨지 무게중심** |
| 음성 ② | 날끝 왼쪽 300px 배경 |

→ 후보 마스크 3장 중 최고 확신도 → 1회 정제 → **날끝 패치**(SAM이 축소 때문에 놓치는
바늘 끝을 실루엣으로 복원, 0~1px까지)

> 음성점을 반대쪽 날 위에 두는 게 중요하다. 크롭에서 기본 위치(이미지 오른쪽 끝)를 쓰면
> 배경에 떨어져 힘이 없고, 마스크가 윗날까지 번진다.

**연한영역 게이트 (`--pale-neg on`, 마모 공구 프레임에만 적용)**

마모 날끝의 뿌옇게 번진 영역을 제외하는 로직. 날끝에서 이어진 연한 픽셀이 **200개 이상**일 때만 발동:

1. 그 영역 무게중심에 음성점 추가
2. 날끝 패치 생략 (패치가 뿌연 부분을 되살려 갈고리 요철을 만들기 때문)
3. 실루엣(밝기<210) 교집합 — 흰 반사 얼룩 제거
4. 모폴로지 열기 27px — 픽셀 톱니 제거
5. 외곽선 원형 이동평균 41점 — 잔물결 제거

> **새 공구는 게이트 대상이 아니다** (항상 날끝까지 잡음). 새 공구에서 발동해 날끝이
> 물러나던 문제(img_0076)를 이렇게 구조적으로 막았다.

### 단계 5 — 서브픽셀 스냅

아래 경계만 **밝기 50% 지점**으로 미세 보정한다 (안쪽 밝기와 배경 밝기의 중간값을 지나는 지점).

**위 경계는 스냅하지 않는다.** 공구 내부 경계라 대비가 없고, 대비가 생기는 유일한 경우가
반대날 정반사 광반이라 오검출만 일으킨다 (img_0076 의 1.37mm 지점에서 21px 점프 → 가짜 72µm 봉우리).

### 단계 6 — 날 짝짓기 + 위상 정합

- **짝짓기**: 2날 대칭이라 새/마모 날 대응이 모호 → 새 2장 × 마모 2장 RMSE 행렬로 direct/swap 자동 결정
- **위상 정합**: 마모 후보 ±3장(`--search 3`) 중 **외곽선 y차 RMSE 최소**인 것 선택
  - 구간: `u = tip-skip ~ adoc × crop-factor` (코팅 1.01~4.00mm)
  - 위·아래 경계 둘 다 사용 (`--rmse-edge both`)
  - 산출물 `pair*_phasematch.png`: 오프셋별 RMSE(파랑)와 후퇴 평균(주황), 선택 지점(빨강)

### 단계 7 — 정렬 + 절삭날 마모 측정 (`top_retreat_align()`)

**두 축을 따로 정렬한다:**

| | 무엇으로 | 왜 |
|---|---|---|
| **가로 dx** | 아래 경계 **형상** 매칭 (2.5~3.9mm, `--base-lo/hi`) | u 원점(날끝)이 두 사진에서 어긋난 것 보정. 세로 오프셋을 뺀 잔차로 판정하므로 배율 잔차와 무관 |
| **세로 영점** | **위 경계** [ADOC, 마스크끝−100px] 중앙값 | 절삭이 안 닿은 구간은 새/마모가 같아야 함 → 남는 차이는 계통 오차 |
| **배율 s** | 지그(조명 구멍) 세로 지름 비 (`--scale-ref jig`) | 세션 간 배율 차이 보정 (≈1.006) |

**절삭날 후퇴 = 정렬 후 위 경계 y차**, 측정 구간 **0~ADOC (날끝 포함)**.

> **시도했다가 버린 방식**: 아래 경계를 높이 기준자로 삼는 방법(아래 경계 차이 중앙값으로 평행이동).
> 아래 경계 자체에 **40µm 수준의 배율 잔차**가 있어 그 오차가 위 경계로 옮겨왔다
> (절삭 구간 밖에서 0으로 안 떨어짐). 그래서 아래 경계는 **가로 형상 참조로만** 쓴다.

아래 경계 반경차(`pair*_retreat.png`)는 이제 **정렬 진단용 참고**다. 마모 수치가 아니다.

#### SAM 체크포인트 — clone 만으로는 안 돌아간다

**체크포인트**란 SAM(Segment Anything Model)의 **학습된 가중치 파일**이다. 우리가 만든 게 아니라
Meta 가 공개한 것이고, 이 파일이 있어야 SAM 이 날 영역을 잡는다.

파일이 **2.4GB** 라 GitHub 에 올릴 수 없다 (파일당 100MB 제한). 그래서 **저장소에 포함돼 있지 않다.**
`git clone` 을 하면 코드는 전부 받아지지만 이 파일만 없고, 그 상태로 옆날 진단을 돌리면
`[SAM] 체크포인트 'sam_vit_h_4b8939.pth' 를 찾지 못했습니다` 오류가 난다.

**해결**: 파일을 따로 구해서 아래 위치에 둔다. 앞사람 PC 에 있는 것을 USB·드라이브로 복사받는 게
가장 확실하다 (공식 배포처에서 받아도 되지만 2.4GB 다운로드다).

```
MAENG-Tool-Wear/          ← 저장소 최상위
├── sam_models/           ← 여기에 둔다 (권장 위치)
│   └── sam_vit_h_4b8939.pth      2.4GB
├── side_ref_angle/       ← 옆날 코드
└── tool_wear_v2/         ← 아랫날 코드
```

코드는 다음 순서로 체크포인트를 찾는다 (`sam_blade_detect.sam_dir()`):

1. 환경변수 `SAM_MODELS_DIR` 로 지정한 폴더 — 드라이브 다른 곳에 두고 싶을 때
2. **저장소 최상위의 `sam_models/`** — 권장. 옆날·아랫날이 같이 쓴다
3. `tool_wear_v2/code/sam_models/` — 옛 위치 (하위 호환용으로 계속 지원)

> 예전에는 2번이 없어서 옆날 코드가 `tool_wear_v2` 안을 들여다봐야 했고, 그래서
> "`side_ref_angle/` 만 딴 데로 복사하면 깨진다"는 제약이 있었다. 지금은 최상위
> `sam_models/` 를 먼저 보므로 그 제약이 없다. 다만 **저장소 폴더 구조 자체는

### ADOC 을 입력하면 무엇이 달라지나

ADOC(축방향 절삭깊이)은 **공구가 소재에 얼마나 깊이 박혀 돌았는지**다. 날끝에서 ADOC 만큼만
실제로 재료를 깎았고, 그보다 위쪽 날은 공중에서 돌기만 했다. 이 한 줄이 세 곳을 결정한다.

| 쓰이는 곳 | 하는 일 | ADOC 2.0 | ADOC 1.5 |
|---|---|---|---|
| **마모 측정 구간** | 최대·평균을 집계하는 범위 = `0 ~ ADOC` | 0~2.0mm | 0~1.5mm |
| **영점(기준선) 구간** | 여기서 새/마모가 같아야 한다고 보고 차이를 0 으로 맞춤 = `ADOC ~ 마스크끝−100px` | 2.0~3.55mm | 1.5~3.5mm |
| **위상 RMSE 상한** | 같은 각도 프레임을 고를 때 비교하는 범위 = `ADOC × crop-factor` | ~4.0mm | ~3.0mm |

**틀리게 넣으면:**

- **실제보다 크게** (1.5인데 2.0 입력) → 안 깎인 1.5~2.0mm 구간이 마모 집계에 섞인다.
  그 구간은 후퇴가 0 이므로 **평균이 실제보다 낮게** 나온다. 최대값은 영향이 적다.
- **실제보다 작게** (2.0인데 1.5 입력) → 영점 구간이 실제 절삭 구간(1.5~2.0mm)을 물고 들어간다.
  진짜 마모가 있는 곳을 "0 이어야 할 곳"으로 삼아 빼버리므로 **전체가 과소평가**된다. 이쪽이 더 위험하다.

> 그래서 **ADOC 은 직경만큼이나 중요한 입력**이다. 가공 조건표에서 확인해 정확히 넣을 것.

### 주요 파라미터

| 인자 | 기본 | 뜻 |
|---|---|---|
| `--diam` | 8.0 | 공구 직경 mm. 스케일 기준 |

## 5. 알려진 문제 / 다음 작업 후보

### 우선순위 높음

1. **코너(0~0.2mm) 수치 신뢰도** — 날2의 624µm 가 코너 값인데, 코너에서는 위/아래 경계가 만나
   dx 보정 전제가 흔들린다. 코너 전용 처리(법선 방향 후퇴 측정 등)를 검토할 것.
   프로토타입 있음: 세션 스크래치의 코너 법선 후퇴 실험.
2. **ALUCUT 날 짝짓기 불확실** — direct/swap 차이가 6.4µm 밖에 안 난다 (코팅은 260µm).
   형상이 달라 RMSE 변별력이 떨어진 것으로 보임. 짝짓기 지표를 보강해야 한다.
3. **배율 기준(지그)의 신뢰성** — 지그는 사실 조명이라 세션마다 변한다(0.65% 관측).
   아래 경계에 남은 40µm 잔차의 유력한 원인. **스케일바 교정**이 근본 해결.

### 우선순위 중간

4. **ALUCUT 형상 일반화** — 무코팅·다른 형상. 램프가 2.23mm까지 길어서 옛 규칙이 깨졌었다.
   현재 방식은 ADOC 기준이라 통과하지만, 3날 이상 공구는 아직 미지원.
5. **수치 파일 저장** — 측정값이 콘솔에만 나온다. CSV/텍스트 자동 저장 필요.
6. **Test1~Test10 마모 진행 곡선** — ALUCUT 세션에 10단계가 다 있다. 사용량 대비 마모
   곡선을 뽑으면 방법 검증과 마모 모델링을 동시에 할 수 있다. **가장 가성비 좋은 다음 실험.**
7. **exe 빌드** — 미완. 두 가지를 먼저 고쳐야 한다:
   (a) GUI가 `sys.executable` 로 스크립트를 실행하는데 exe 에서는 자기 자신을 가리킨다 → 동일 프로세스 실행으로 분기 필요
   (b) `sam_blade_detect.py` 의 체크포인트 경로가 `__file__` 기준이라 exe 안에서 임시폴더를 가리킨다
   참고: torch+CUDA 4.4GB + 체크포인트 2.4GB → 배포 7GB 규모. 아랫날 전용 경량 exe 도 선택지.

### 폐기된 접근 (다시 시도하지 말 것)

- **날끝 연한 픽셀 직접 제거(`--tip-trim`)** — 픽셀 단위로 깎아내니 경계가 울퉁불퉁해진다.
  대신 SAM 음성점으로 알려주는 게 맞다 (현재의 연한영역 게이트).
- **아래 경계를 높이 기준자로** — 위 4.2절 참고. 배율 잔차가 옮겨온다.
- **위 경계 스냅** — 정반사 오검출만 생긴다.
- **전처리(CLAHE/스트레치)** — SAM 검출 개선 없음, CLAHE 는 비선형이라 스냅 기하를 왜곡.
- **영점을 1차 직선 맞춤으로** (`--zero-fit linear`, 코드에서 제거함) — 무절삭 구간에
  직선을 맞춰 기울어진 배율 잔차까지 빼려는 시도. 그 구간 곡선이 직선이 아니라
  기울기가 구간 선택에 따라 요동치고, 그걸 절삭 구간으로 **외삽**하면 오차가 증폭된다.
  실측: 같은 공구인데 두 날의 기울기가 **부호까지 갈렸고**(코팅 +7.9 vs −0.5µm/mm,
  crop-right 2.0 에서는 +74.1 vs −26.5), 평균 후퇴가 208µm 로 폭증하거나 −22µm 로
  음수가 되는 등 붕괴했다. **영점은 중앙값 상수만 쓴다.**
- **크롭 오른쪽을 2R(직경)로 넓히기** (`--crop-right 2.0`, 옵션은 남아 있음) —
  해상도 손실이 없고(SAM 은 긴 변인 높이 기준으로 축소) 영점 구간이 2~3배 길어지는데도,
  두 날의 영점 일치도가 **오히려 나빠졌다**(코팅 차이 5.3 → 22.2µm). 넓힌 구간의
  배율 잔차가 위치에 따라 변해 중앙값이 절삭 구역 근처에서 틀어지기 때문.
  ALUCUT 에서는 위상 선택 프레임까지 바뀌었다. **기본 1.0 유지 권장.**
  (다른 공구·배율에서는 유리할 수 있어 옵션은 남겨뒀다. 이미지 여유가 부족하면
  실행 시 경고가 나온다 — ALUCUT 은 2.0 에서 여유가 32px 뿐이다.)

## 7. 옆날 + 아랫날 동기화 이후 가능한 작업

현재 두 파이프라인은 **완전히 독립**이다. 옆날은 절삭날 후퇴(µm)를, 아랫날은 밑면 기하로
날 후퇴(µm)를 각각 낸다. 같은 공구·같은 시점 데이터인데 결과가 따로 논다.

### 동기화란 무엇인가

같은 Test 폴더에 대해 두 진단을 **한 번에 돌리고 결과를 하나로 묶는 것**. 필요한 작업:

1. GUI에서 한 번 지정하면 `Toolwear/옆` 과 `Toolwear/아래` 를 둘 다 진단
2. 결과 폴더 통합 (`<시각>_<공구>/side/`, `<시각>_<공구>/bottom/`)
3. 공통 요약 파일(CSV/JSON): 공구명, 시각, 옆날 날별 최대/평균, 아랫날 날별 후퇴, 스케일, 경고 플래그
4. **날 번호 대응** — 옆날의 pair1/pair2 와 아랫날의 날1/날2 가 같은 물리적 날인지 맞춰야 한다.
   (회전 위상 기준이 서로 달라서 자동 대응이 안 된다. 이게 기술적 핵심 난제.)

### 동기화되면 할 수 있는 것

| 작업 | 내용 | 왜 동기화가 필요한가 |
|---|---|---|
| **교차 검증** | 같은 날의 마모를 옆·밑 두 방향에서 독립 측정 → 일치하면 신뢰도 급상승 | 날 번호 대응이 맞아야 비교 가능 |
| **3D 마모 형상** | 옆면 후퇴(축방향 분포) + 밑면 후퇴(반경방향 분포)를 합쳐 코너 마모를 입체로 기술 | 두 측정이 같은 좌표계로 묶여야 함 |
| **VB 정의 통일** | ISO 플랭크 마모 폭 vs 윤곽 후퇴 — 두 방식 값이 다르다. 같은 날에서 동시 측정하면 환산 관계를 실측할 수 있다 | 미해결 과제였음 (DESIGN.md 참고) |
| **마모 진행 곡선** | Test1~10 전체를 자동 배치 처리 → 사용시간 대비 마모 곡선, 수명 예측 | 배치 실행 구조가 있어야 실용적 |
| **이상 조기 경고** | 두 측정이 갈리는 시점 = 치핑 같은 국소 파손 신호일 수 있다 | 동시 측정이라야 의미 있음 |
| **실시간 모니터링 통합** | 현재 실시간 탭은 아랫날만 자동 진단. 옆날까지 확장하면 새 Test 폴더가 생길 때 양쪽 자동 처리 | GUI 구조 통합 필요 |

### 추천 순서

1. **먼저 `Test1~10` 배치 실행 + 요약 CSV** (동기화 없이도 가능, 가장 빨리 성과)
2. 결과 폴더·요약 형식을 옆/아랫날 공통으로 정리
3. 날 번호 대응 문제 해결 (회전 위상 기준 통일)
4. 그 다음 3D 형상·VB 환산 같은 응용
